# Shervan Jassim portfolio

A small static website for GitHub Pages. Content, images, routes and the desktop/mobile compositions are retained from the original portfolio. There is no Squarespace runtime, Jekyll, JavaScript framework, package manager or external font service.

## Update the website

1. Fetch/pull the latest changes in GitHub Desktop before editing.
2. Edit the relevant HTML fragment in `src/pages/`.
3. Run these commands from this project folder:

       python3 build.py
       python3 check.py
       python3 -m http.server 8000

4. Open http://localhost:8000 and review the changed pages on desktop and mobile. Refresh after edits. Stop the server with Ctrl+C.
5. Review and commit both your source edits and generated pages in GitHub Desktop. Push the `simplify-portfolio` branch for review. Merge to `main` only when ready to publish.

GitHub Pages continues to publish the root of `main`. No hosting configuration change is needed. Changes on `simplify-portfolio` do not update the live site.

## Where to edit

| Change | Source file |
| --- | --- |
| Navigation or header | `src/templates/header.html` |
| Footer | `src/templates/footer.html` |
| Shared metadata/page shell | `src/templates/page.html` |
| Text and image placements | `src/pages/*.html` |
| Titles, descriptions, preview images and routes | `src/pages.json` |
| Typography, spacing, image fitting, responsive styling | `assets/site.css` |
| Local font declarations | `assets/fonts.css` |
| Mobile-menu behaviour | `assets/site.js` |

The root `index.html`, `about/index.html` and `portfolio/*/index.html` files are generated by `build.py`. Make content changes in `src/`, then rebuild; edits made directly to generated HTML are overwritten.

## Images and layouts

Keep images in `assets/` and use root-relative paths such as `/assets/app_nav_cover.png`. Existing image files have not been recompressed or altered. `asset-manifest.json` is a historical record of image provenance; its original Squarespace URLs are not loaded by the website.

Case-study layouts use CSS Grid. Each section specifies its mobile and desktop row counts. Each block has `--area` (mobile) and `--area-wide` (desktop), in the order `row-start / column-start / row-end / column-end`. These positions preserve the existing layouts and do not need editing for small text changes. Review larger content changes at both widths.

To add a case study, duplicate a suitable fragment, add its route and metadata to `src/pages.json`, add its card to `src/pages/home.html`, and update neighbouring previous/next links. Rebuild and run the checker.

The old `/kontakt/` address redirects to the homepage. `.nojekyll` and `CNAME` must stay in the repository root. All live preview metadata uses the domain in `CNAME`.

## Requirements

Python 3.8 or later, with no third-party packages. The browser JavaScript only manages the mobile menu. Preview through the local server rather than opening HTML files directly, because asset paths start at the site root.
